## 当前完整调用链

`9 套 SVG 预设 → svg-render 二维预览 → Qwen 文本工具调用输出 diff → 宿主验证/事务式插入 SVG → 当前版本 SVG → 确定性结构解析 → Pascal MCP 六个工具 → 校验、原子保存 → 原生三维查看器`。

1. **真实 AI 在 Step2 参与。** 使用现有 gufo 服务，实际响应模型标识 `Ours`，启动参数包含 `--think off`。交接文档称其为 Qwen3.8-35B-A3B；本轮没有重新核验权重文件/量化版本，具体权重为 **UNKNOWN**。模型容器启动时间保持 `2026-10-19T12:32:12.302163471Z`。
2. 新增卫生间采用宿主从真实房间多边形计算并预校验的角部候选；Qwen 根据需求选择候选并输出明确的两墙、一门、一标签 diff（本轮角部间距 1.5m 是实验设计参数，不是旧房屋量测值），返回后再次校验。**不是让语言模型凭空生成三维网格，也不是图片生成。** 推拉门只能落在有剩余空间的真实客厅/阳台共墙上。
3. Step3 不调用视觉模型，也不再执行原来结果未被强制采用的 LLM 复核。墙 path 的 evenodd 子路径先构造占据区，门窗屏障封闭连通域，保留凹形房间轮廓；尺寸链分别换算 X/Y 比例并处理 viewBox 偏移。无目录固定外轮廓、无运行时 annotation JSON 模板。
4. MCP 的 `svg-deterministic/v1` 模式重新解析 `sourceSvg`，要求提交的墙/房间/门窗与解析结果一致，直接复用现有编译和家具工具；不运行通用分区猜测和门窗自动迁移/裁剪。现有 Blueprint 校验阈值未放宽。
5. V1/V2 各保存自身 XML；编辑基准、当前显示版本和三维输入分别解析，不回退到“最近一次 XML”。缺失 XML 的旧预览版本明确拒绝。完成事件要求版本 hash 匹配；刷新后将 SVG 场景识别为权威来源，避免被目录模型覆盖。失败回滚，SVG 错误不降级为目录模型。

## 使用与回退

刷新 3002 后重新选择已替换的 9 套 SVG；旧的 svg-edit 预览若没有保存 XML，需重新生成。部署主机须保留现有 `/usr/share/fonts/opentype/noto` 字体目录；字体与配置仅只读挂载给 web。部署需同时指定：

```bash
docker compose -f compose.migration.yaml -f compose.svg-adapter.yaml up -d --no-deps web pascal-mcp
```

只用原 compose 启动会恢复旧镜像。需要回退本轮服务时，可使用原 compose 的同一条 up 命令，不加 SVG override；模型容器不受影响。测试入口在 `tests/svg-adapter/`，`run-in-image.sh` 只供一次性镜像容器覆盖源文件后运行，不应在正在服务的生产容器执行。
