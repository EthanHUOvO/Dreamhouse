# 客餐厅四向墙角新增卧室：修改与实测

本轮基于用户要求恢复的卧室版本，修改基线为实际运行目录 `/srv/ideal-home/rocm-migration` 的 `v2-svg` 分支 `4e3620b`。Dreamhouse/CIIE 是发布副本；原 `/home/amd/Workspace/Ideal-house` 未改动。

## 已实现并验证的范围

- 新增一个卧室支持图上、下、左、右；未指定方向或“方向不限”时搜索四向。必须依靠既有墙角形成矩形，门通向剩余客餐厅。
- 仅旋转搜索坐标，再将候选坐标映射回原 SVG；不旋转或重绘原图。统一搜索用墙段方向，复用既有 SVG 增量墙门工具。厨卫、其他房间、原门窗位置及连接保护仍执行。
- 矩形不只检查外接框：额外拒绝超出名义矩形的分支，检查实际矩形内部，保留原有尺寸、面积守恒、局部外轮廓和通行校验。
- 新增隔墙、门、卧室及剩余客厅面积来自同一 SVG；二维预览和实际 Pascal MCP 使用同一 SVG。Qwen 解析需求并选择真实候选 ID，不能直接提供可信坐标；图像模型不参与结构真值生成。
- 首次生成的默认沙发原先可能被放到厨房门口。现在仅对增量卧室图的首次默认摆放检查真实资产尺寸、墙体余量与可通行门洞，必要时换用可验证的初始位置/朝向。原始目录默认摆放路径保持原逻辑；显式传入或已保存家具绕过默认生成器，完整保留原位置、旋转、资产和材质。
- 同时检查新增卧室和原本可通行的客厅侧门路。按真实门宽和漫游碰撞判断可穿过的开口位置，原场景与新场景分别使用自己的宿主墙 ID；不靠放宽碰撞半径、删除家具或忽略新增阻断通过。
- 搜索最多尝试96个完整候选，约12秒后停止继续搜索。已找到的候选逐个通过校验才能使用；无候选时区分面积不足、无支持墙角、几何拒绝与搜索上限。搜索停止不证明建筑上无解。

程序参数仍为：卧室至少6㎡、净短边至少2m、剩余客厅至少7㎡、几何通道0.9m、新门0.8m；家具场景使用原漫游半径0.22m及0.08m网格。它们是当前概念工具的筛选参数，不能等同施工、采光、消防或无障碍认证。
