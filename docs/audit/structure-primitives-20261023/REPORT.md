## 本轮范围与实际链路

新增分割房间、合并相邻房间、移动共享隔墙三类结构原语，保留既有新增卫生间/推拉门及经典上侧卧室工具。自然语言由现有本地文本接口真实解析成最多四步操作；可信宿主根据当前 SVG 计算候选，模型选择真实候选 ID，宿主复算并校验。模型不直接提供可信墙体坐标。

流程为：选中版本 SVG → AI 结构化计划 → 主机几何候选 → AI 选择 → 全部操作在内存执行 → 同一可见 SVG 渲染二维图 → 独立 Pascal MCP 解析并构建三维 → 同源家具保留、门高度、碰撞与物理通行检查 → 陈旧请求检查 → 同时提交图片版本和 SceneGraph。任何一步失败都保持原版本，不返回可提交的中间改造。图像模型继续用于视觉预览，不是结构真值。

新 SVG 使用可见米制房间多边形、墙与门窗线条，不依赖隐藏 JSON 替换画面；Web 和 MCP 同步解析。保留房间 ID，合并时维护房间映射，删除共享隔墙及明确属于两房的内部开口；移动隔墙复用原编辑工具并联动宿主门窗。分割保留凹形轮廓、新隔墙和真实门，检查原入口连续接近区及 0.9m 通道。

## 已确认的限制

1. 九套原图加载、保存恢复通过，不代表九套任意改造都通过。当前“客餐厅分出书房”的九套程序回归中 one-option-01 有可验证候选，其余八套触发安全计算预算，保持原图。预算拒绝不证明建筑上无解，也不能算改造成功。
2. 分割后可能与已保存沙发或床冲突；家具不会自动移位、删除或替换。one-option-01 的书房/经典卧室初次生成可通过，保留原场景 Sofa 的相关测试应安全拒绝，需要先在 Step3 手动调整并保存。合并、隔墙移动和组合操作另有原家具保留的正例。
3. 原有 Kitchen 家具越界仍存在。若不涉及该房间，保留家具并明确警告；不能宣传整体家具布局已全部修复。新增碰撞、原本可达房间或门接近区被阻断均拒绝。
4. three-option-03 原始房间多边形存在精确铺合缺口；普通加载通过，但严格结构编辑需先修正源数据。没有放宽拓扑校验来绕过问题。
5. 合并目前支持完整共享墙段；移动支持可验证的近直共享墙链、整数厘米、最多 1.5m。分割是有上限的正交多边形候选搜索；未指定位置时按固定方向顺序选择首个可验证方向，计算预算耗尽整次回滚。
6. 现有手动墙门修改若未回写 SVG，拒绝以旧二维基准覆盖；保留锁墙/锁门窗和开启方式。跨步骤引用本次新建房间、任意曲墙、多户型随意重画及任意约束组合尚未验证。
7. 面积为当前解析中心线多边形面积，不是原图标注净面积。0.9m 通道和 0.22m 漫游半径为软件校验参数，不能代表施工、消防、采光、通风或承重安全认证；这些仍为 **UNKNOWN**。
8. 本轮未改造 Step4 图像模型接入/画质。推送后的 [GitHub 自动 CI](https://github.com/EthanHUOvO/Dreamhouse/actions/runs/39971195860) 实际 **FAIL**：旧 24 套目录的 `test:pascal-v2` 报 21 条房间顶点越界，错误文本与上一轮 CI 逐条完全相同，见 `evidence/github-ci.json`。当前九套 SVG 目录及结构原语专项回归单独通过；不能宣称全项目 CI 通过。
9. 中间构建 b0aa 的书房实际请求曾一次返回 `SVG_EDIT_FAILED`，之后真实重放和最终构建均通过；首次原因仍 **UNKNOWN**，证据保留于 `evidence/incidents/`。成功重放不等于已经定位或修复该次异常。

## 部署与复现

只更新 Web 与 Pascal MCP 解析器，模型服务保持原容器；镜像及部署健康检查见 `evidence/deployment.json`。离线增量构建依赖该主机已有基础镜像，不是空白机器安装器。

```sh
docker compose -f compose.migration.yaml -f compose.primitives.yaml up -d --no-deps --no-build pascal-mcp web
```

可复现测试入口：`tests/structure-primitives/README.md`、`run-regression.py`、`live-http.py`、`live-validate.ts`。真实推理脚本默认访问隔离测试端口 13024，不会自动向生产发起生成任务。敏感配置未纳入报告。
